# Contributing to bookmark-sync

Thanks for your interest in contributing! This document covers the dev environment, the workflow, and the one legal requirement we have on every commit (the DCO sign-off).

## Developer Certificate of Origin (DCO)

All commits must be signed off. By signing off you certify that your contribution is your own work (or you have the right to submit it) under the project's license, per the [Developer Certificate of Origin](https://developercertificate.org/):

```text
Signed-off-by: Your Name <your.email@example.com>
```

The easiest way: commit with `git commit -s` (add `-s` on every commit; use `-s --amend` to add it to your last commit). Commits without a sign-off cannot be merged — the repository runs a DCO check on pull requests.

This project deliberately uses the DCO instead of a CLA: you keep copyright, and your contribution is licensed under AGPL-3.0-or-later together with the rest of the project.

## Getting started

Requirements: Node.js 20+, pnpm, and (for Firefox builds/testing) a Chromium and a Firefox install.

```bash
git clone https://github.com/catnuko/bookmark-sync.git
cd bookmark-sync
pnpm install
pnpm dev            # local preview of the options/popup UI
```

## Useful commands

| Command | What it does |
| --- | --- |
| `pnpm build` | Chromium build → `extension/` |
| `pnpm build:firefox` | Firefox build → `extension-firefox/` |
| `pnpm test` | vitest unit tests |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm lint` | oxlint over `src/`, `scripts/e2e/`, `tests/`, `website/` |
| `pnpm fmt:check` | format check (oxfmt) |
| `pnpm check` | typecheck + lint + fmt + tests — run this before opening a PR |

## Where things live

- `src/` is the **source of truth** for the extension (options page, popup, MV3 service worker, sync engine, CRDT, crypto).
- `supabase/` holds the database migrations and edge functions. Migrations are plain SQL files, applied in order.
- `scripts/e2e/` has the multi-browser end-to-end scenarios (see `scripts/e2e/README.md`).
- Build outputs (`extension/`, `extension-firefox/`, `dist/`) are never committed.

## Commit and PR conventions

- Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, etc. Releases are generated by release-please from these.
- One logical change per PR; include tests when you change sync/CRDT/crypto behavior.
- CI runs the quality gate (typecheck + lint + format + tests) on PRs. Run `pnpm check` locally first — it is the same set of checks.

## Reporting bugs and security issues

- Bugs and feature requests: open a GitHub issue (templates provided).
- **Security vulnerabilities: never in a public issue** — see [SECURITY.md](SECURITY.md).
