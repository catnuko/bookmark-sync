# Chrome 双子树时代，「同一棵书签树」到底是什么意思

2025 年 6 月起，Chrome 把书签从一棵树拆成了两棵：syncing（账号）与 non-syncing（本地）。登录后你的书签栏可能出现两套文件夹，之前「同步 = 一棵树到处一致」的直觉变得不再显然。但同步引擎内部维护的仍然是一棵以 ROOT_UUID 为根的 CRDT 逻辑树——Chrome 的两棵树和 Firefox 的多根，都被归一化成了这棵树的固定根。这篇讲清这是怎么做到的。

## 背景：Chrome 从一棵树变成了两棵

2025 年 6 月起，Chrome 把书签树拆成两棵平行子树：

- **syncing 子树**（账号）：跟随 Google 账号同步的书签，登录后出现
- **non-syncing 子树**（本地）：只在本机存在的书签

更麻烦的是 Chrome 官方明确警告**不能用 id 或 name 认根**（`id` is not fixed），只能按 `folderType` 认类型、按 `syncing` 认子树。旧实现把根写死成 `0`/`1`/`2`/`3`，于是账号子树被整棵跳过——账号书签静默不同步。

树的形状还会随登录状态变化：

| 状态 | 出现的根 |
|---|---|
| 未登录 | 只有本地根 |
| 已登录 + 本地为空 | 只有账号根（本地文件夹被隐藏） |
| 已登录 + 本地非空 | 两棵都在 |

所以每轮同步都要重新解析根，不能缓存成常量。

## 同步引擎看到的不是浏览器树，是一棵逻辑树

浏览器给你看的是「多棵根」，同步引擎维护的是一棵**逻辑树**：所有固定根都并列挂在 ROOT_UUID 之下，共 8 个：

- 本地 4 个：书签栏、其他书签、移动书签、书签菜单
- 账号 3 个：账号书签栏、账号其他书签、账号移动书签
- 加上 ROOT 本身

Chrome 的账号根与本地根是**并列**的固定根（不是 alias），chromeId ↔ uuid 仍是 1:1。Firefox 没有双子树，它的 menu / toolbar / unfiled / mobile 四个原生根通过静态 id 表映射到同一套固定根。受管书签（managed）等浏览器内部文件夹被显式忽略，不会误当固定根。

同步引擎把书签操作转成 MoveOp（Kleppmann 树 CRDT），多设备按 Lamport 时间戳收敛：同一条书签树，两边各自增删改，同步后结构一致、不丢书签、不成环。

## 所以「同一棵书签树」还准确吗

分两个层面看：

- **逻辑层面：准确。** 同步的就是一棵单根 CRDT 逻辑树，跨设备收敛到同一结构。这正是宣传语「保持同一套书签结构」的技术含义。
- **UI 层面：有差异。** Chrome 登录 + 本地非空时，本机会同时显示账号与本地两套顶层文件夹，用户看到的是「多棵根」而不是一棵树。宣传语描述的是同步后的逻辑结构，不是浏览器 UI 的单根展示。

还有一个容易忽略的点：**本地（non-syncing）子树也在同步范围内**。一台设备/一个浏览器资料绑定一个空间，本机书签树整体等于该空间——所以「Chrome 只同步账号书签」的直觉在这里不成立，本地书签同样会跨设备一致。

未登录的设备通过**回退文件夹**承载账号内容：同步引擎会在「其他书签」下建同名文件夹，登录后真账号根出现，回退自动退休，不会出现同一 CRDT 子树在本机有两份表示的问题。

## 对你意味着什么

1. 登录 Chrome 后看到账号/本地两套书签栏，是双子树的正常表现，不是同步坏了
2. 换设备登录同一账号，账号树与本地树的内容都会保持一致
3. 书签出现「落错文件夹」时，先看它属于账号子树还是本地子树，再判断是否是映射问题

## FAQ

### Chrome 更新后书签栏出现了两套文件夹，是同步坏了吗

不是。2025 年 6 月起 Chrome 双子树让账号书签与本地书签成为并列的两套根，登录且本地非空时两者同时显示。同步引擎把两套都归一化进同一棵逻辑树，不会互相覆盖。

### 未登录的设备能收到账号书签吗

能。账号根在未登录设备上没有真实落地位置时，同步引擎会在「其他书签」下建一个同名回退文件夹承载它；设备登录后真账号根出现，回退文件夹自动退休。

### 本地（non-syncing）书签也会同步到其他设备吗

会。本机书签树整体绑定到一个同步空间，本地子树同样进 CRDT 树。这是与 Chrome 官方「non-syncing 仅本机」语义的不同之处：使用本扩展后，本地书签也跨设备一致。

### Firefox 没有双子树，会不会少同步一部分

不会。Firefox 的 menu / toolbar / unfiled / mobile 四个原生根通过静态 id 表映射到同一套固定根 UUID，账号根内容通过回退文件夹落地。无论哪端，同步的都是同一棵逻辑树。
