# Edge 收藏夹并入 Chrome：最简单的迁移，和「删掉又冒出来」那个问题

Edge 到 Chrome 是所有迁移里最轻的一个：两边都是 Chromium 内核，书签格式完全兼容，同一份 HTML 文件导进去基本不会出错。但「简单」不等于「无损」——Edge 的「集」功能和 `edge://favorites` 路径带不走，还有一个困扰很多人的问题：收藏夹删掉之后又冒出来。这篇讲清边界和做法。

## 先说好消息：这是格式最兼容的一对

Edge 和 Chrome 都基于 Chromium，共用同一套书签内部格式。这意味着两件事：

1. **HTML 导出/导入在这两边几乎不会丢结构。** 相比 Chrome 换 Firefox（Firefox 的 `BookmarkTreeNode` 没有 `folderType` 也没有 `syncing`）、或 Safari 换 Chrome（plist 二进制 + 无对应概念），Edge 换 Chrome 是格式层面最干净的一条路。
2. **两边都用同一套浏览器扩展 API。** 任何基于 `chrome.bookmarks` 的扩展在 Edge 和 Chrome 上行为一致，不需要为哪个单独适配。

所以如果你只是想「把 Edge 的收藏夹搬到 Chrome，之后不再用 Edge」，原生导入就是正确答案，不需要任何第三方工具。数据全程在你本机。

## 迁移前要知道什么

### 带得走的和带不走的

| 项目 | 能带走吗 | 说明 |
|---|---|---|
| 书签条目（URL + 标题） | 能 | 完整保留 |
| 文件夹层级（含嵌套） | 能 | Edge 的层级结构直接映射到 Chrome |
| 文件夹顺序 | 能 | 同格式，顺序保留 |
| 「集」（Collections） | **不能** | Edge 独有概念，Chrome 无对应 |
| 收藏夹路径 | **不能** | `edge://favorites` 里的路径规则不适用于 Chrome |
| 密码、扩展、浏览记录 | 不在此列 | 属于浏览器配置文件，不属于书签 |

### Edge 的「集」在 Chrome 里没有对应概念

Edge 的「集」（Collections）是它把相关收藏夹组织在一起的功能——一个「集」里可以放多个文件夹和书签，形成一个跨目录的逻辑分组。Chrome 没有这个概念，它的组织方式只有「文件夹」这一种，是严格的树形结构。

迁移后你会失去的是**跨目录的分组视图**：如果你的收藏夹是按「集」组织的，导进 Chrome 后它们会变成一堆平铺的顶层文件夹。「集」不会作为一个整体被保留，也不会变成文件夹。

> 这不是导出出错，是目标浏览器没有这个功能。要保留「集」的组织意图，迁完之后手动建一个同名的 Chrome 文件夹把它们放进去——一次性工作。

### `edge://favorites` 里的路径不适用于 Chrome

Edge 内部管理收藏夹的页面是 `edge://favorites`，Chrome 对应的是 `chrome://bookmarks`。这条本身只是地址不同，但有一个实际后果：**任何你收藏在 Edge 收藏夹里、指向 `edge://` 内部页面的链接，在 Chrome 里点不开。**

Chromium 允许把内部页面地址收藏成书签，Edge 里的收藏夹确实会积累这类条目。迁到 Chrome 后它们还在，但点了没反应，因为 Chrome 不认 `edge://` 这个协议。遇到这种书签直接删掉就行。

### 「刚删掉又冒出来」的真实原因

这是 Edge 用户最常搜的一个长尾问题，值得单独讲，因为它经常被误判。

Edge 开着同步的情况下，你在 Edge 里删掉一条收藏夹，刷新一下或者换台设备，它又回来了。这通常不是 bug，而是**两套同步引擎在打架**：

1. Edge 自带的同步（登录 Microsoft 账号）会把你的删除操作上传到微软的云。
2. 如果你还装了某个第三方同步工具（或者 Chrome 侧有另一个账号在同步同一批书签），它也记着那条书签还在。
3. 两个引擎各自认为对方是权威，结果就是删除被反复拉回来。

另一个很常见的原因是**路径匹配**。如果某个工具存书签时用的是路径字符串（比如 `收藏夹栏/工作/工具`），你删掉「工作」这个文件夹后，工具看到的是「原来的 `收藏夹栏/工作/工具` 不见了」，但下一轮同步时那个路径又出现了——因为它匹配的是路径，不是节点身份。这类工具在删掉又把文件夹建回来之后，看起来就像「删了又冒出来」。

**怎么分辨你遇到的是哪一种？** 把 Edge 的同步关掉，单独观察：

- 关掉之后不再冒出来 → 是两套同步引擎冲突
- 关掉之后还冒出来 → 是工具的删除逻辑有问题，试试把文件夹改名而不删（如果改名后不再复活，说明它匹配的是路径）

> 最直接的解法是**只留一套同步引擎**。Edge 已经登录微软账号在同步了，就不要再加第二个工具去同步同一批书签。要么用 Edge 原生同步，要么用跨浏览器工具但把 Edge 的原生同步关掉。

## 两条路径

| 对比项 | 原生导入（Edge 导出 HTML → Chrome 导入） | 跨浏览器同步工具 |
|---|---|---|
| 迁移成本 | 最低，格式同源几乎不丢 | 需要安装配置 |
| 结构完整性 | 好（同格式），仅丢 HTML 本身的限制 | 好，按节点身份同步 |
| 后续在 Edge 继续用 | **不再同步**，两边独立 | 保持一致 |
| 解决「删掉又冒出来」 | 不能，那需要改同步机制 | 能（前提是只留一套引擎） |
| 数据经过谁 | 只有你自己 | 工具的服务器（默认 AES-GCM 加密，服务端只存密文） |

**关键区分：原生导入是「一次性搬家」，同步工具是「跨浏览器持续同步」。** 对 Edge→Chrome 尤其要说清楚：如果 Edge 只是你为了某个旧系统装的、之后不开了，原生导入十分钟搞定，别引第三方。但如果 Edge 和 Chrome 你都要长期用，甚至两边还想偶尔互相同步，那才轮到工具。

## 动手步骤

### 路径一：原生导入（只迁这一次）

1. 在 Edge 地址栏输入 `edge://favorites` 打开收藏夹页面。
2. 找一下你收藏的 `edge://` 内部页面链接（搜 `edge://` 就知道有多少），这些在 Chrome 里点不开，迁之前先心里有数，迁完直接删。
3. 在收藏夹页面右上角（或书签管理器里）找到导出选项，导出为 HTML 文件。建议**只导出要迁的那几个文件夹**，不要全选——全选会把一堆你几年没点过的旧链接一起拖过去。
4. **打开导出的文件看一眼。** 如果你记得有「中间层没有直接书签」的文件夹，搜一下确认还在。Edge→Chrome 是同格式，这条一般不会中招，但看一眼比中招后再查便宜。
5. 装好 Chrome 后打开 `chrome://bookmarks`，右上角三点菜单 →「导入书签和设置」。
6. 选 HTML 文件，指向第 3 步的文件。导入位置选「导入的书签文件夹」，不要直接覆盖已有书签。
7. 导入后按下面「怎么验证」对一遍。特别要检查两件事：`edge://` 开头的书签（点了没反应），以及多出来的空目录。

### 路径二：用跨浏览器同步保持一致

如果 Edge 和 Chrome 你都要长期用：

1. 确认你要用哪一套同步。Edge 如果开着微软账号同步，**先把它关掉**（Edge 设置 → 账户 → 关闭「同步收藏夹」），否则两套引擎会打架。
2. 在 Edge 和 Chrome 两侧都装 BookmarkSync 扩展，登录同一个账号。Edge 侧是 Chromium 内核，`chrome.bookmarks` API 在 Edge 上原生可用，不需要额外适配。
3. 拉取完成后两边的书签树一致，文件夹改名和移动会互相同步。改名只改 `title` 字段，移动只改子节点的 `parentId`，节点 ID 不变，所以结构不会因为改名而塌。
4. 遇到删不掉的条目时，改名或移动代替删除——在按节点身份同步的实现里，移动只改父子关系，能安全绕开「删除被同步引擎判定为路径变化」的坑。

BookmarkSync 支持 Chrome、Edge、Firefox，**Safari 暂不支持**。额度上免费档 500 条 / 1MB / 1 个空间，Plus 10,000 条 / 20MB / 3 个空间，Pro 不限条数 / 500MB / 10 个空间，可绑不同浏览器资料。加密默认 AES-GCM 开启，服务端只存密文。

## 怎么验证迁移成功

1. **对总数。** 分别数 Edge 和 Chrome 的书签条数（不含文件夹），对不上先查是不是把文件夹算进去了，或者某条重复。
2. **抽查层级。** 挑两三个你印象深的嵌套文件夹，逐层点开确认。同格式迁移这里基本不会出问题，但抽查比通读便宜。
3. **清掉 `edge://` 书签。** 在 Chrome 书签管理器里搜 `edge://`，把结果全选删掉。这些留着就是点了没反应的死链。
4. **检查重复项。** 如果你两边都有同一批书签，导入前没清理，合并后会出现重复条目。搜一下你最常去的那几个站点，确认没有出现两份。
5. **如果「删掉又冒出来」之前就存在**，按上面那节说的做：关掉一套同步引擎再观察。如果关掉之后仍然复活，就试一次「改名代替删除」，看改名后还会不会回来——这是分辨路径匹配还是节点身份的最快办法。

## FAQ

### Edge 收藏夹怎么导入 Chrome？

最简单的方式是导出 HTML 再导入：在 Edge 打开 `edge://favorites`，导出书签为 HTML 文件，然后在 Chrome 的 `chrome://bookmarks` 页面右上角三点菜单选「导入书签和设置」，选 HTML 文件那一项。Edge 和 Chrome 同为 Chromium 内核，格式完全兼容，这是格式层面最干净的一条迁移路径，正常情况下不会丢层级。

### Edge 的「集」能一起迁到 Chrome 吗？

不能。集是 Edge 独有的概念，Chrome 只有「文件夹」这一种组织方式，是严格的树形结构，没有跨目录的分组视图。迁移后你的内容都在，但「集」作为一个整体不会保留，会变成一堆平铺的顶层文件夹。要保留组织意图，迁完手动建一个同名 Chrome 文件夹把它们归拢进去。

### 为什么 Edge 收藏夹删掉之后又冒出来？

通常不是 bug，是两套同步引擎在打架。Edge 自带同步会把删除上传，另一套工具（或者 Chrome 侧另一个账号）还记着这条书签存在，两边互相覆盖，删除就被拉回来。另一个常见原因是工具用路径字符串匹配书签——你删掉一个文件夹，它下一轮看到路径消失又出现，就当成没删。解法是只留一套同步引擎：Edge 已经在同步就不要再加第二个；要跨浏览器同步就把 Edge 的原生同步关掉。

### 迁到 Chrome 后 Edge 里的书签还能继续用吗？

能用，但要分清两种情况。用原生导入的话，两边从此**不再同步**，你在 Edge 里的改动不会到 Chrome，反之亦然。如果需要两边持续一致，就用跨浏览器同步工具：它按节点身份（节点 ID + `parentId`）同步，Edge 和 Chrome 都基于 Chromium，共用同一套 `chrome.bookmarks` 扩展 API，行为一致，不需要为哪个单独适配。

### 收藏在 Edge 里的 `edge://favorites` 链接，迁到 Chrome 还能打开吗？

打不开。`edge://` 是 Edge 内部的协议，Chrome 不认，点了没反应。Chromium 允许把内部页面地址收藏成书签，所以这类条目在迁移后依然存在但是死的。在 Chrome 书签管理器里搜 `edge://` 就能全部找到，删掉即可。同理，指向 `chrome://` 的书签在 Edge 里也是打不开的。

### 迁移前需要关掉 Edge 的同步吗？

如果只用原生导入，不需要，两边从此独立。但如果装了跨浏览器同步工具在两边跑，**应该关掉 Edge 的原生同步**。两套引擎同时管理同一批书签时，删除和新增的冲突无法避免，表现就是「刚删掉又冒出来」。只留一套同步引擎是最省事的解法。
